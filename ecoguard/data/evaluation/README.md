# Evaluation Cases

Artificial cases used to measure the response planner. Each one is shaped exactly as the
risk analysis agent hands work to the response planning agent, so replaying it through
`plan_response(detected_event, risk_assessment)` is a faithful reproduction rather than
an approximation.

These are **committed inputs**, not generated output — that is why they live here and not
in `data/generated/`.

## Running the suite

```bash
python scripts/run_response_plan_evaluation.py --dry-run    # validates everything, no API calls
python scripts/run_response_plan_evaluation.py              # full run, needs ANTHROPIC_API_KEY
```

Results land in `data/generated/evaluation/`, with `latest.md` as a stable path for a demo.

## What a case contains

| Field | Purpose |
| --- | --- |
| `case_id`, `title`, `hazard` | Identity. |
| `probes` | What this case is designed to test. |
| `notes` | Author-facing. What is artificial about the case and why it exists. |
| `expected_behaviour_notes` | Author-facing. What a sound answer looks like. |
| `detected_event` | First planner argument, in the internal `DetectedFireEvent` shape. |
| `risk_assessment` | Second planner argument, in `RiskAnalysisAgent` shape. |

**`notes`, `probes` and `expected_behaviour_notes` are never shown to the judge.** There
is no reference answer in this design: the judge reasons from the protocol corpus, not
from a crib. A test asserts the leak cannot happen, and the runner's `--dry-run` checks
it too.

## The eight cases

| Case | What it probes |
| --- | --- |
| `fire-01-apartment-town` | Proportionality in a residential building. Must not reach for wildland tactics. |
| `fire-02-telegram-wildfire-large` | Legacy downstream uncertainty fixture; not an operational Telegram-only detection path. |
| `fire-03-carmel-wui-extreme` | Critical mobilisation, evacuation, safety preconditions. |
| `fire-04-negev-open-nothing-nearby` | **Over-response.** The correct plan here is minimal. |
| `fire-05-stale-weak-detection` | Stale evidence, and that gap-filling search must *not* fire. |
| `fire-06-degraded-all-sources-failed` | Honesty when every enrichment source failed. |
| `fire-07-industrial-zone` | Area-type inference, and whether the planner invents hazmat protocol. |
| `fire-08-detection-unavailable` | The gate. Must refuse, at zero model cost. |

The suite deliberately includes cases where **doing little is the right answer**. A suite
where every case is critical measures nothing about proportionality, and over-response is
as much a failure as under-response.

## Editing or adding a case

Cases are generated by `scripts/build_evaluation_cases.py`, which pulls citation text out
of the live corpus at build time rather than trusting a hand-copied quotation. Edit the
case definition there and re-run:

```bash
python scripts/build_evaluation_cases.py
pytest tests/test_evaluation_cases.py
```

A quotation that no longer appears in the corpus fails the build immediately, rather than
surfacing later as a pipeline failure and being debugged in the wrong place.

## Adding a hazard

The judge is hazard-agnostic and needs no code changes:

1. `data/protocols/<hazard>/` with documents and a manifest.
2. `data/evaluation/<hazard>_cases/` with cases.
3. `--hazard <hazard>` on the runner.

**But the pipeline is not hazard-agnostic.** `RiskAnalysisAgent.analyze_event` skips any
event whose `event_type` is not `"fire"`, and both its prompts are fire-specific. Adding a
flood corpus readies the judge for flood; it does not make the planner produce flood
plans.

## What the score means

A **judged quality score**, not an accuracy measurement. There is no ground truth — nothing
defines the single correct plan for a wildfire — so the number is one model's
protocol-grounded opinion of another model's plan.

Read `weakest_dimension` before the headline figure. It answers "what should we fix",
which is the question the suite exists for.

Two further caveats worth stating in any write-up:

- **The pipeline is not deterministic.** Adaptive thinking has no seed and Sonnet 5 accepts
  no temperature control, so a single run is a sample. Use `--repeat 3` to see the spread,
  and `--no-search` to remove the live web as a second source of variation.
- **Judge and planner share a model family**, so they share blind spots. The judge's
  independent retrieval at a larger `top_k` mitigates this; it does not remove it.
